# 1-minute QMT-faithful backtest engine

A minute-level backtest engine that **runs real QMT model-backtest strategy
scripts unchanged**, reading QMT's own local `.DAT` minute data and reproducing
A-share matching (the part QMT keeps closed-source).

Goal: a strategy you backtest here ports 1:1 to the live QMT GUI model engine,
because it calls the *same* globals (`passorder`, `order_target_value`,
`get_trade_detail_data`, `get_market_data_ex`, …) against the *same* data bytes.

Two things are deliberately **not in git**:

* **`data/`** -- 2.6 GB of run output, a single blotter up to 387 MB, all of it
  regenerated by a run.
* **`qmt_reference/`** -- verbatim copies of QMT's own shipped scripts
  (`qmttools/`, `xtconstant.py`, the example strategies), kept locally as a
  reference for what the live GUI engine does. They are the vendor's code, so
  they are not redistributed here; every QMT install already has them.

Input data lives outside this folder and is not part of the repo either:
`C:\AI_STOCK\dataset\1min_parquet\` and `C:\AI_STOCK\dataset\duckdb\tushare.duckdb`.

## How it mirrors QMT

| QMT concept | here |
|---|---|
| main-chart bar timeline (`load_main_history`) | `driver_code` (000001.SZ) `.DAT` → `timelist` |
| `run_bar`: `for i: C.barpos=i; handlebar()` | `runner.Engine.run` |
| `C.get_bar_timetag`, `get_market_data_ex` | `context.ContextInfo`, `datafeed` |
| `passorder` / `order_target_value` globals | `api.build_globals` (closures over the account) |
| `get_trade_detail_data(...,"ACCOUNT"/"POSITION")` | `account.detail_account/detail_positions` |
| C++ closed matcher (fills, fees, T+1) | `account.Account` (reimplemented, A-share rules) |

`timetag` is milliseconds, UTC-based, exactly like QMT
(`datetime.utcfromtimestamp(timetag/1000)+8h` == Beijing).

## QMT .DAT minute format (datadir\<MKT>\60\<code>.DAT)

* 8-byte header `struct "<2i"` = `(-2, 2147483647)`
* then 64-byte records `struct "<8iqiffiii"`:
  `ts(s,UTC), open, high, low, close, 0, volume(shares), 526, amount(int64),
   status(14=09:30/13=cont/18=14:58-59 auction/15=15:00), 1.0f, 1.0f, preclose, 0, 32763`
  (prices are ×1000). Confirmed against `qmt_backtest/convert_external_1min_to_qmt_dat.py`.

python run_ml_backtest.py 20180101 20181231
# full run

Matching model (`account.CostModel`, set in `run_ml_backtest.py`), this
account's actual terms:

| term | rate | side |
|---|---|---|
| commission | 0.00008 (wan 0.8), **no minimum** | both |
| regulatory fee | 0.0000625 (wan 0.625) | both |
| transfer fee | 0.00001 (wan 0.1) | both |
| stamp tax | 0.0005 since 2023-08-28, 0.001 before | sell only |
| slippage | 0 bps | -- |

One full round trip is 8.05 bps. QMT's own defaults are all-zero; these are
set here. Every knob has a CLI override (`--commission-rate`,
`--regulatory-fee`, `--slippage-bps`, `--per-order-fee`).

> The regulatory fee was **not modelled at all before 2026-09-02**. It is
> 1.25 bps per round trip, so a monthly-rebalanced book was running about
> 15 bps a year too cheap. `--regulatory-fee 0` reproduces the older runs.

Order fill rule: an order placed in `handlebar` at bar *T* matches immediately
against the **same code's bar at T** at that bar's close (±slippage). If the code
has no bar at *T*, the order is rejected and the strategy retries later — this is
exactly what the ML strategy's `pending_sells` loop expects, and what happens for
delisted/renamed codes QMT's instrument master also rejects.

## Known limitation — mark-to-market between rebalances

The imported `.DAT` only covers **rebalance windows** (each held name has ~52
days), not continuous history. So:

* ✅ Each holding's P&L is captured correctly (buy-day and sell-day bars are both
  real), so **rebalance-to-rebalance and total return are right**.
* ⚠️ On non-rebalance days held names have no bar, so NAV is held flat between
  rebalances → **daily volatility / Sharpe / max-drawdown are understated**.
* ⚠️ Index `.DAT` (000300.SH) is equally sparse, so the benchmark column uses the
  full-coverage driver (000001.SZ) instead of a real index.

To get a continuous daily NAV and a real index benchmark, mark held positions on
non-rebalance days from **daily** closes (e.g. the project's `tushare.duckdb`).
This is a planned optional hook (`Engine.mark_holdings` would consult a daily
source when no minute bar exists).

## Publishing

`origin` carries **one commit**: the current tree, nothing before it. Do not
`git push` -- run

```bash
./publish.sh "what changed"
```

which force-pushes a throwaway single-commit orphan branch over `origin/master`.
Local `master` keeps the real history and deliberately does not track `origin`.
Same policy as the [qmt_trading_scripts](https://github.com/1527248147/qmt_trading_scripts)
repo, which holds the live execution scripts that mirror
`strategies/qmt_combo_top20_twap.py`.
